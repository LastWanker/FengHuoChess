# 开发日志：V3随机性失效与修复
日期：2026-03-12  
项目：FengHuoChess  
主题：V3 在 value 重排分支绕过 softmax 采样，导致对战阶段随机性失效

---

## 1. 问题重申
在 `scripts/logs/v3模型巨大随机性问题` 中，第五阶段晋升（duel）出现明显异常：

1. `duel-r1` 和 `duel-r2` 长期呈现固定的 `240:0` / `0:240` 极端结果。
2. 即使候选模型是“在 best 上小幅训练得到”，对战仍然表现为高度一边倒。
3. 只有混入 baseline/random 对手时，才勉强能看到随机性。

这与我们期望的“模型侧使用 top-k + 温度 softmax 采样”不一致。

---

## 2. 根因定位
根因在 `src/fenghuo_chess/ai/model_v3.py` 的 `ModelAISourceV3._choose_action_with_value`：

1. 当 `decision_beta <= 0` 时，会走 `_sample_from_topk`，有随机性。
2. 但当 `decision_beta > 0` 时，原逻辑在 value 重排后直接贪心返回 `scored[0]`。
3. 这会绕过 `sample_top_k + sample_temperature`，等效于关闭采样。

结论：V3 并非“没有随机参数”，而是“在 value 分支没有生效”。

---

## 3. 修复内容
### 3.1 恢复 value 分支采样
在 `ModelAISourceV3._choose_action_with_value` 中改为：

1. 先按 `combined score` 排序；
2. 再对 `scored` 调用 `_sample_from_topk`；
3. 仅在采样关闭/失败时退回 top-1。

这样保证无论是否启用 value 重排，都遵循统一的采样入口。

### 3.2 默认 beta 统一调整为 0.5
按当前策略将默认值改为 `0.5`，已同步到：

1. `src/fenghuo_chess/ai/model_v3.py`
2. `src/fenghuo_chess/ai/selfplay_league.py`
3. `scripts/eval_v3_model_ai.py`
4. `scripts/export_v3_selfplay_data.py`
5. `scripts/run_v3_league_cycle.py`

---

## 4. 轻量验证结论（非重型测试）
1. 同一局面重复采样时，`sample_top_k=3` 已出现多动作分布，不再单点锁死。
2. 小规模 `pool_mode=mirror`（V3 vs V3）对局，胜负不再固定复制，首手也出现多样性。

说明本次修复至少已恢复“采样入口生效”这一关键行为。
