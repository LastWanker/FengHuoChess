# 第三步：自博弈擂台升级（League）

## 本步定位

- 目标：在可控风险下让模型迭代，不靠主观“看起来变强”。
- 交付：仅新增 1 个代码文件。
- 新增文件：`src/fenghuo_chess/ai/selfplay_league.py`

## 设计原则（符合当前接口）

使用现有能力直接拼装：

- 对局执行：`run_selfplay(...)` / `MatchRunner`
- 数据导出：`TraceRecorder` JSONL
- 策略插拔：`PlayerSource`（Teacher / Model / Random）

## 文件内核心职责

`selfplay_league.py` 一文件内实现：

- `LeagueConfig`
  - `promotion_threshold`（如 0.55）
  - `arena_games`（如 200）
  - `opponent_pool`（teacher/old_best/random 比例）
- `run_arena(best_source, candidate_source, games) -> stats`
- `should_promote(stats, threshold) -> bool`
- `run_league_round(...) -> RoundResult`

## 迭代流程（单轮）

1. 用 `best_model` 生成自博弈数据（可混入 teacher 对手）
2. 外部训练得到 `candidate_model`
3. 固定局数擂台：`candidate` vs `best`（黑白轮换）
4. 胜率过阈值才升级，否则丢弃候选

## 验收标准

- 升级完全由胜率阈值驱动（非人工拍脑袋）。
- 每轮输出：样本数、局数、胜率、是否升级。
- 连续多轮运行时，`best_model` 不出现明显回退。

## 一次性实现建议

- 先交单文件 `selfplay_league.py`（含最小 CLI 或函数入口）。
- 训练过程先外置；league 先把“评估与升级判决”闭环跑通。
- 稳定后再拆分 `dataset/train/arena` 多文件架构。
