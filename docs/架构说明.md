# 架构说明

项目采用 `src` 分层结构，核心分为 5 层：

- `constants/`：配置和文案常量。
- `domain/`：领域模型与纯规则（不依赖 pygame）。
- `services/`：可复用业务服务（出锋、悔棋历史、模式切换）。
- `application/`：流程编排控制器（`GameController`）。
- `ui/`：pygame 事件循环与渲染实现。

## 主流程

1. `ui/pygame_main.py` 处理输入事件。
2. 通过 `application/game_controller.py` 调用业务动作（落子、悔棋、重开、切模式）。
3. 控制器串联 `domain.rules + services.exposure_service + domain.scoring`。
4. `ui/renderer.py` 根据 `GameState` 绘制界面。
5. 文案播报由控制器下发事件，`ui/broadcast.py` 负责动画显示。

## 悔棋设计

- 使用 `HistoryService` 的 `snapshots + cursor` 语义。
- 每个“完整回合结算后”存一次快照，`undo` 每次只回退一个快照。
- 避免旧实现里“入栈时机与弹栈策略不一致”导致的一次回退多步问题。
