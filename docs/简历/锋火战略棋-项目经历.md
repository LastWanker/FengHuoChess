# 锋火战略棋（FengHuoChess）- 简历项目经历（可直接使用）

## 一、简历可直接粘贴版（推荐）

我独立设计并实现了原创棋类项目 **FengHuoChess**（Python + Pygame + NumPy + PyTorch），从规则定义、UI 交互到 AI 训练闭环全部自研。规则采用 **四阶段动态战场**（3x3→5x5→9x9→15x15）、阶段化胜利条件与“出锋-截锋”惩罚机制，并实现终局三连计分。工程上完成了领域规则与 UI 解耦，统一逻辑 API（`legal_actions/apply_action/simulate_action`），支持 PVP/PVE/EVE、无界面自博弈、结构化对局导出（JSONL）。AI 方面构建了从随机/规则老师到模型对手，再到联赛晋升的完整训练体系，包含多进程数据生成、长度桶平衡、hard-case 加权、counterexample 样本、黑白双模型对抗晋升与课程化参数调度。项目累计跑通多轮大规模实验（单轮 2000~2400 局、单批 3 万~7 万步样本），并持续迭代随机性治理（统一 top-k+temperature 采样链路、修复 value 分支绕过采样问题），显著提升了训练稳定性与可解释性。

## 二、面试展开版（详细）

### 1) 我负责的核心工作

- 原创规则设计与落地：定义四阶段战场扩张、阶段胜负条件切换、阶段 2/3 出锋-截锋连锁结算、阶段 4 三连计分。
- 产品化交互：设计并实现完整 Pygame UI（介绍页选手配置、模式切换、战场高亮、播报动画、终局弹层、终局后悔棋/重开）。
- 架构升级：将规则与状态推进抽到 `domain + application/logic_api`，UI 与 AI 共用同一规则源，支持 headless 运行。
- AI 对手体系：实现 `PlayerSource` 抽象，统一接入 Human/Random/Heuristic/Model/V3Model。
- 训练工程化：搭建「导出 -> 筛样 -> 训练 -> 擂台评估 -> 晋升」脚本链路，并扩展 V3（CNN+Temporal Transformer+Value 决策）独立流水线。
- 稳定性治理：围绕随机性、数据分布、对战公平性做持续诊断与修复（含日志体系、参数课程化、晋升门槛联判）。
- 质量保障：补齐 unit/integration 测试，覆盖 `simulate_action` 无副作用、出锋判定、终局后 UI 行为、悔棋快照语义等关键路径。

### 2) 技术与设计亮点（容易被忽略但很加分）

- 规则层细节：
- 阶段 3 在 slow 模式下将出锋触发阈值从 3 连提升到 4 连，和 fast 模式形成节奏差异。
- 出锋检测按锚点+方向扫描并去重，同一回合可处理多条连线及连锁截锋。
- 暴露惩罚后立即复检胜负，避免“惩罚落子已致胜但状态未终局”的漏洞。

- 对局体验细节：
- UI 模式中 AI 回合统一最小延迟（1s），保证人类可观察性；headless 模式去延迟以提升吞吐。
- 终局遮罩与 `game_over` 解耦：关闭弹窗不会错误恢复对局，且终局后悔棋/重开仍可用。
- 重开采用二次确认防误触；历史系统采用 `snapshots + cursor`，一次 `undo` 只回退一个完整快照。

- AI 决策细节：
- 规则老师 AI 在阶段 1（3x3）启用小规模求解（minimax 递归缓存），避免开局无意义随机。
- 大分支局面先做候选裁剪（即时胜/必防守/cheap score），再做模拟评分，降低算力开销。
- 模型 AI 全量合法动作 mask，非法落子 logits 置 `-inf`，推理过程天然规则一致。

- 训练与数据细节：
- 自博弈样本不是简单堆叠：按对局长度 x 胜方颜色分桶均衡，且坚持 no-dup（目标受最小桶约束）。
- hard-case 机制：针对 baseline/teacher（V3 为 baseline/v2best）对局中的失败样本加权，提升难例学习占比。
- counterexample 机制：对“前期崩盘”来源局面注入反例标签，在训练中以负向目标约束过度自信动作。
- V3 时序训练采用滑窗与边界强化采样（跨 9/10、25/26 边界加权 + critical collapse 加权）。
- 晋升评估采用双向换边（candidate 黑/白各打一轮）+ baseline 对照联判，避免单色优势或样本偏置导致误晋升。

- 随机性治理（重点）：
- 统一模型随机入口为 `top-k + temperature softmax`，弱化旧的“次优动作概率”双轨机制冲突。
- 引入主/次种子混合与分环节 seed（导出/筛样/训练/擂台），提升可复现实验能力。
- 修复 V3 value 决策分支绕过 softmax 的问题，确保启用 value 重排时仍保留采样随机性。
