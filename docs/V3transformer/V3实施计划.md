# FengHuoChess V3（CNN + Temporal Transformer + Value决策）实施计划

## 1. 目标与边界

### 1.1 目标
1. 在不破坏 V2 现有联赛链路的前提下，新增一套完全独立的 V3 训练/评估/联赛通路。
2. V3 数据保留双方完整落子时序，不再用黑白拆分清洗打断时间序列。
3. V3 模型引入时间维度建模：CNN 负责空间特征，Transformer 负责跨步时序关系。
4. V3 推理把 value 纳入落子决策（而非仅训练辅助）。
5. 维持黑白双权重分离（best/candidate black + white），但两侧训练均使用完整共享时序数据。

### 1.2 非目标（本期不做）
1. 不改造 V2 的旧脚本和旧权重目录。
2. 不在第一版引入 MCTS 或大规模搜索树。
3. 不在第一版引入超长对局记忆（先做固定窗口时序）。

## 2. V2/V3 隔离原则

### 2.1 版本命名
1. 现有链路定义为 `V2`。
2. 新链路定义为 `V3`。

### 2.2 目录隔离（必须执行）
1. `artifacts/v2_*` 不新增、不改名，保持现状可复现。
2. V3 独立目录：
   - `artifacts/v3_transformer/models/`
   - `artifacts/v3_transformer/datasets/`
   - `artifacts/v3_transformer/cache/`
   - `artifacts/v3_transformer/logs/`

### 2.3 脚本隔离（必须执行）
1. 基于 V2 脚本复制出 V3 脚本，不在老脚本上直接叠功能。
2. V3 新脚本建议：
   - `scripts/export_v3_selfplay_data.py`
   - `scripts/curate_v3_dataset.py`
   - `scripts/train_v3_model.py`
   - `scripts/eval_v3_model_ai.py`
   - `scripts/run_v3_league_cycle.py`

## 3. V3 数据方案（保留完整时序）

### 3.1 原则
1. 每条样本必须可回到 `(game_id, step_index)`，按升序还原完整棋局。
2. 不再输出 `trace_black` / `trace_white` 两条时序被裁剪的数据。
3. 黑白模型分开训练，但均读取同一份共享时序数据（通过 seed/init 区分模型演化）。

### 3.2 数据格式
1. 继续沿用现有单步字段：`state/action/player/outcome/legal_actions`。
2. 保留并强制校验：`game_id`、`step_index` 连续性。
3. 在 curation 后新增索引缓存（避免每轮重复分组）：
   - `artifacts/v3_transformer/cache/train_seq_index.pkl`
   - `artifacts/v3_transformer/cache/val_seq_index.pkl`

### 3.3 样本构造（时间窗口）
1. 设时间窗口 `T`（首版建议 8 或 12）。
2. 对每个目标步 `t`，取 `[t-T+1, ..., t]` 的状态序列，不足前缀用零状态 pad。
3. 监督目标：
   - policy 目标：第 `t` 步真实 action。
   - value 目标：第 `t` 步当前落子方 outcome（沿用 `-1/0/1`）。
4. 切窗方式使用 `stride=1` 的滑动窗口（每一步都可成为监督目标），不做随机硬切段。

### 3.4 阶段边界处理（新增，重点）
1. 不建议“5步一段”固定切块。固定小段会打断关键上下文，尤其对 `25/26` 转折不友好。
2. 不做“25前一段 + 26后一段”的硬分割；分界线应被高频跨越采样而不是被切断。
3. 采用“滑窗 + 边界强化”而不是“随机分段”：
   - 常规窗口：覆盖同阶段内部演化。
   - 跨界窗口：显式覆盖 `9/10`、`25/26` 前后上下文。
4. 训练采样按类型加权（首版建议）：
   - 同阶段窗口：权重 `1.0`
   - 跨 `9/10` 窗口：权重 `1.5`
   - 跨 `25/26` 窗口：权重 `2.0`（你定义的超级危险分界线）
5. 对局阶段强约束可按步号做辅助标签（用于采样/统计，不替代规则阶段）：
   - `S1: 1~9`
   - `S2: 10~25`
   - `S3: 26~80`
   - `S4: 81+`
6. 窗口长度建议用“分层长度”而非统一短窗口：
   - `S1` 主采样：`T=6~8`
   - `S2` 主采样：`T=10~12`
   - `S3` 主采样：`T=12~16`
   - 训练时可在上述范围随机取 `T`，但必须保留跨界窗口高权重。
7. 增加“临界崩盘样本”标记（用于加权，可选辅助任务）：
   - 定义示例：`t<=25` 且该方在 `N` 步内（如 `N=6`）快速转负/输棋。
   - 目标：让模型学到“前25手布局质量”对 `26+` 生死的延迟影响。

## 4. V3 模型方案（CNN + Temporal Transformer）

### 4.1 首版结构
1. 每步状态先经 CNN 编码为空间向量（或小特征图+池化）`h_t`。
2. 序列 `[h_{t-T+1} ... h_t]` 输入因果 Transformer Encoder（只看过去和当前）。
3. 取末位 token 输出：
   - policy head -> 225 logits（15x15）
   - value head -> 标量 `[-1,1]`

### 4.2 推荐首版超参（先小后大）
1. `T=8`
2. `d_model=128`
3. `n_heads=4`
4. `n_layers=3`
5. `ffn_dim=256`
6. `dropout=0.1`

## 5. V3 推理决策（value 参与落子）

### 5.1 决策流程
1. 先用 policy logits + legal mask 取 top-k 候选（建议 k=5）。
2. 对每个候选动作做一步快速模拟，得到下一状态 `s'`。
3. 估计 `V(s')`，并转换到“当前决策方视角”。
4. 组合评分并重排候选：
   - `score(a) = alpha * log_pi(a|s) + beta * V_root(s'_a)`
5. 按评分贪心或 softmax 采样执行动作。
6. 推理侧维护最近 `T_max` 步滚动缓存（如 16），每步取末端窗口，不做分段重置。

### 5.2 视角转换规则（必须落实）
1. 训练中的 value 是“当前落子方视角”。
2. 模拟一步后轮到对手走，模型输出 `V(s')` 默认是“对手视角”。
3. 转回根节点视角时取负号：`V_root(s') = -V_model(s')`。

## 6. 联赛流程（V3 独立）

### 6.1 V3 回合流程
1. `export_v3_selfplay_data.py`：导出原始完整时序对局。
2. `curate_v3_dataset.py`：做长度/胜负/难例平衡，但不按 player 丢行。
3. `train_v3_model.py`：
   - 训练 `candidate_black`（init `best_black`，共享 trace）
   - 训练 `candidate_white`（init `best_white`，共享 trace）
4. `eval_v3_model_ai.py`：快速 sanity + 回归检查。
5. `run_v3_league_cycle.py` duel 晋升（沿用双向换边公平评估）。

### 6.2 V3 默认权重路径
1. `artifacts/v3_transformer/models/model_v3_best_black.pt`
2. `artifacts/v3_transformer/models/model_v3_best_white.pt`
3. `artifacts/v3_transformer/models/model_v3_candidate_black.pt`
4. `artifacts/v3_transformer/models/model_v3_candidate_white.pt`
5. `artifacts/v3_transformer/models/model_v3_shared_bootstrap.pt`

## 7. 分阶段实施计划（可直接执行）

## Phase 0：脚手架与路径隔离
1. 复制 V2 主脚本到 V3 命名脚本。
2. 全部默认输入输出路径切到 `artifacts/v3_transformer/*`。
3. 新脚本参数与 V2 对齐，先保证“同功能可跑通”。

验收标准：
1. V2 脚本行为与输出不变。
2. V3 跑一轮 smoke 后仅写入 V3 目录。

## Phase 1：V3 数据管线改造
1. `curate_v3_dataset.py` 去掉黑白行过滤，保留完整步序。
2. 增加时序样本索引缓存生成。
3. 提供数据一致性检查（同 game_id 的 step_index 单调）。
4. 在索引中增加窗口类型标记：`intra_stage`、`cross_9_10`、`cross_25_26`。
5. 实现边界加权采样器，优先覆盖 `25/26` 转折窗口。

验收标准：
1. 抽检若干 game_id 可完整恢复原对局顺序。
2. 训练集/验证集索引缓存可复用且可重现。

## Phase 2：V3 模型与训练
1. 实现 `src/fenghuo_chess/ai/model_v3.py`（CNN+Temporal Transformer）。
2. `train_v3_model.py` 支持序列 dataset、policy+value 联合训练。
3. checkpoint meta 写入：`version=v3, arch=cnn_temporal_tf, window=T`。
4. 可选增加辅助头（或加权损失）学习“临界崩盘风险”，默认低权重开启。

验收标准：
1. 单卡/CPU smoke 可完成 1~2 epoch。
2. loss 可下降，输出 checkpoint 可被 V3 推理脚本加载。

## Phase 3：V3 value 驱动决策
1. 实现 `ModelAISourceV3`（或在 source 工厂中注册 v3 专用 source）。
2. 接入 top-k + one-step simulation + value 重排。
3. 增加可调参数：`--decision-top-k --decision-alpha --decision-beta`。

验收标准：
1. 相同 seed 下决策结果稳定可复现。
2. 关闭 `beta` 时行为退化为 policy-only（用于回归对比）。

## Phase 4：V3 联赛跑通与对照实验
1. `run_v3_league_cycle.py` 打通 5 段流程。
2. 先做小规模（200/50）再做中规模（2000/300）实验。
3. 固定随机种子做 V2 vs V3 对照统计。

验收标准：
1. V3 全链路 3 轮无中断。
2. 给出 duel 胜率、baseline 胜率、平均步数、推理耗时四项对照。

## 8. 风险与应对

1. 风险：时序模型在 CPU 推理变慢。
   - 应对：减小 `T/d_model/layers`；优先在 pool/arena 使用 CUDA。
2. 风险：value 直接参与决策导致风格突变。
   - 应对：先小 `beta`（如 0.15），并保留 policy-only 开关。
3. 风险：序列样本构造引入标签错位。
   - 应对：加入单测，校验 `x_seq[-1]` 对应 `y_action_t`。
4. 风险：黑白模型逐渐同质化。
   - 应对：保留分开 init + 分开 seed + 分开 duel 晋级门槛统计。

## 9. 测试与验收清单

1. 单元测试
   - 序列切窗正确性
   - 因果 mask 正确性
   - value 视角转换正确性（一步模拟后取负）
   - 边界窗口标记正确性（`cross_9_10` / `cross_25_26`）
   - 采样权重生效性（边界窗口抽中率高于同阶段窗口）
   - 临界崩盘样本标记正确性（标签与回放对齐）
2. 集成测试
   - V3 导出/清洗/训练/duel 全链路 smoke
   - V2 与 V3 互不污染路径
3. 性能测试
   - 单步推理耗时
   - arena 每千局耗时

## 10. 首轮建议参数（Smoke）

2. `arena-games=50`

4. `batch-size=64`
5. `window=8`
6. `decision-top-k=5`
7. `decision-alpha=1.0`
8. `decision-beta=0.15`

## 11. 执行顺序建议（从今天开始）

1. 先完成 Phase 0 + Phase 1（确保数据与路径彻底分家）。
2. 再完成 Phase 2（先跑通训练，不接决策）。
3. 再接 Phase 3（value 决策开关默认 off，A/B 验证后再默认 on）。
4. 最后做 Phase 4 多轮对照，确认稳定后再考虑 UI 入口接入 V3。
